## Directory Purposes

**`src/`**
- Purpose: Core Python implementation of Layers 0–3
- Contains: Pipeline (data fetch, features, regime), backtest engine, strategy lab (generation, registry, validation), ML model (placeholder), hedge engine (placeholder), risk engine (placeholder)
- Key files: `data_pipeline.py`, `backtest_engine.py`, `strategy_generator.py`, `dashboard.py`

**`mql5/`**
- Purpose: MQL5 code for Layer 4 (EA) and Layer 3b (risk rules in terminal)
- Contains: Expert Advisor, risk management includes, order/position management utilities
- Status: Placeholder structure only (`.gitkeep` file); full implementation pending

**`docs/`**
- Purpose: Technical specifications for each layer; reference for implementation decisions
- Contains: Glossary (finance terms), specs for strategy lab, hedge engine, ML model, risk engine + EA
- Key usage: Read relevant `*_spec.md` before implementing corresponding layer (e.g., read `hedge_engine_spec.md` before implementing Layer 2)

**`.claude/skills/`**
- Purpose: Domain knowledge for Claude Code; auto-loaded when relevant
- Contains: Quant finance math (cointegration, HMM, Kelly criterion), MQL5 EA patterns
- Usage: Referenced automatically when working on statistical code or MQL5 files; see SKILL.md in each subdirectory

**`.planning/codebase/`**
- Purpose: Architecture & structure documentation generated by GSD mapper; read by `/gsd-plan-phase` and `/gsd-execute-phase`
- Contains: ARCHITECTURE.md (layers, components, data flow), STRUCTURE.md (this file; file locations, naming, where to add code)

**`output/`**
- Purpose: Runtime-generated data (git-ignored)
- Contains: SQLite strategy registry, CSV of cointegrated pairs, parquet feature files, backtest results
- Not committed to git; recreated on each pipeline run

## Key File Locations

**Entry Points:**
- `src/data_pipeline.py`: Command-line script; main() at end; run with `--mode synth` (default) or `--mode mt5`
- `src/strategy_generator.py`: Command-line script; main() at end; run after data_pipeline completes
- `dashboard.py`: Streamlit app; run with `streamlit run dashboard.py` after strategy_generator completes
- `mql5/ScalpingEA.mq5`: MQL5 entry point (placeholder); runs in MT5 terminal (future)

**Configuration:**
- `requirements.txt`: Python package list (pandas, numpy, statsmodels, hmmlearn, scikit-learn, lightgbm, streamlit, plotly, pyarrow)
- `PipelineConfig` dataclass in `src/data_pipeline.py`: Symbols list, timeframe, window sizes, MT5 credentials; modify for different markets/timeframes
- `DEFAULT_THRESHOLDS` dict in `src/backtest_engine.py`: Approval gates (min trades, profit factor, Sharpe, drawdown); adjust based on trader risk tolerance

**Core Logic:**
- `src/data_pipeline.py`: Fetch OHLCV (MT5 or synthetic) → engineer features → detect cointegration & regime → save outputs
- `src/backtest_engine.py`: Simulate hedge strategy given price pair + parameters; compute stats without lookahead bias
- `src/strategy_generator.py`: Generate random/mutated parameters → run backtest → save to registry → iterate generations
- `src/strategy_registry.py`: SQLite schema & CRUD functions for persisting tested strategies

**Testing & Validation:**
- `dashboard.py`: UI for inspecting backtest results, filtering by pair/status, viewing equity curves & trade lists
- Strategy lab outputs: `output/strategy_lab.db` (queryable via `strategy_registry.list_strategies()`, `get_strategy()`)
- Approval logic: `backtest_engine.validate_strategy()` checks stats against `DEFAULT_THRESHOLDS`

**Documentation:**
- `docs/strategy_lab_spec.md`: Explains Layer 0.5 design (why PnL in "R", approval gate logic, how to use)
- `docs/hedge_engine_spec.md`: Specifies Layer 2 (entry conditions, exit conditions, output format); read before implementing hedge_engine.py
- `docs/ml_model_spec.md`: Specifies Layer 1 (feature inputs, output format, training approach)
- `docs/risk_engine_mql5_spec.md`: Specifies Layers 3 & 4 (Kelly sizing, exposure limits, kill-switch, EA structure)
- `ARCHITECTURE.md`: High-level system design (5 layers, why separated, typical trade flow)
- `ROADMAP.md`: Status of each layer, decision history, next steps by priority

## Naming Conventions

**Files:**
- Python source: `snake_case.py` (e.g., `data_pipeline.py`, `backtest_engine.py`, `strategy_registry.py`)
- MQL5 source: `PascalCase.mq5` (e.g., `ScalpingEA.mq5`)
- MQL5 includes: `PascalCase.mqh` (e.g., `RiskGuard.mqh`, `PositionManager.mqh`)
- Config/data: lowercase or UPPERCASE (e.g., `requirements.txt`, `ARCHITECTURE.md`, `ROADMAP.md`, `CLAUDE.md`)

**Directories:**
- Lowercase, plural or singular noun (e.g., `src/`, `docs/`, `mql5/`, `output/`, `.claude/`, `.planning/`)

**Functions/Classes:**
- Python: `snake_case()` for functions, `PascalCase` for dataclasses/classes (see `PipelineConfig`, `GaussianHMM` from hmmlearn)
- MQL5: `PascalCaseFunction()` and `UPPERCASE_CONSTANT` (per MQL5 conventions)

**Variables:**
- Loop counters: `i`, `j`, `n` (indices); `gen` (generation number)
- Series/arrays: `price_a`, `price_b`, `spread`, `zscore`, `beta`, `correlation`, `returns`, `volatility`
- Dicts: `params` (strategy parameters), `record` (strategy registry row), `stats` (computed statistics), `trades` (list of completed trades)
- Config: `cfg` (PipelineConfig instance)

**Database/Output Files:**
- `strategy_lab.db`: SQLite registry for all tested strategies (primary output from Layer 0.5)
- `hedge_candidates.csv`: CSV from Layer 0; columns: pair_a, pair_b, correlation, coint_pvalue, is_cointegrated, hedge_ratio_beta, spread_zscore
- `features_<SYMBOL>.parquet`: Parquet from Layer 0; per-symbol features including close, log returns, rolling volatility, regime label, z-score, range %

## Where to Add New Code

**New Feature (Price/Regime Indicator):**
- Add to `src/data_pipeline.py`, function `engineer_features()`
- Example: if adding "momentum indicator", compute it as rolling window on log returns, add column to output dataframe, ensure it's included in feature parquets saved to `output/`
- Tests: none yet (future: add to `.testing/` directory if created)

**New Strategy Parameter:**
- Add to `PARAM_RANGES` dict in `src/strategy_generator.py`; define (min, max) bounds
- If parameter is an integer (max_hold_bars), add key name to `INT_PARAMS` set
- Add to `backtest_engine.run_hedge_backtest()` function signature and logic
- Backtest will automatically generate combinations and test them

**New Entry/Exit Condition:**
- Modify `run_hedge_backtest()` logic in `src/backtest_engine.py`, inside the main loop (around line 107–143)
- Example: to add "correlation breakdown" exit, check if rolling correlation falls below threshold and set `exit_reason = "correlation_breakdown"`
- If condition requires new parameters, add to `PARAM_RANGES` in strategy_generator.py

**New Approval Gate Criterion:**
- Add to `DEFAULT_THRESHOLDS` dict in `src/backtest_engine.py` (line ~196)
- Add check in `validate_strategy()` function (line ~204+); append failure reason to `failures` list if threshold not met
- Example: to require minimum average hold bars, add `if stats["avg_hold_bars"] < thresholds.get("min_avg_hold_bars", 10): failures.append(...)`

**New Symbol or Market (MT5):**
- Modify `PipelineConfig.symbols` list in `src/data_pipeline.py` (line ~70)
- If using MT5 real mode, ensure symbol name matches MT5 broker nomenclature (e.g., "EURUSD" vs "EUR/USD")
- If testing with synthetic mode, add entry to `synth_betas` dict (line ~157) with estimated hedge ratio for the new symbol

**New ML Model (Layer 1):**
- Create `src/ml_model.py` (currently placeholder)
- Read spec in `docs/ml_model_spec.md` for expected interface
- Must accept feature parquets from Layer 0 (output/features_<SYMBOL>.parquet)
- Must output: direction (1, 0, -1), confidence (0–1), per symbol per bar
- Must handle regime input from Layer 0 (condition predictions on regime label)

**New Hedge Engine Logic (Layer 2):**
- Create/extend `src/hedge_engine.py` (currently placeholder)
- Read spec in `docs/hedge_engine_spec.md` for entry/exit rules and output format
- Should read outputs from Layer 0 (cointegration test results, z-score, correlation, regime)
- Optional: consume Layer 1 (ML signal) to refine entry direction
- Output: proposed orders (action, pair_a, pair_b, side, size_notional_usd, reason, timestamp)

**New Risk Rule (Layer 3):**
- Add to `src/risk_engine.py` (currently placeholder) or `mql5/RiskGuard.mqh` (currently placeholder)
- Read spec in `docs/risk_engine_mql5_spec.md`
- Validate/reject/size orders from Layer 2; enforce Kelly fraction, max exposure, drawdown limit, kill-switch
- Must be deterministic (no ML); must work offline if Python link drops (duplicate logic in EA)

**New MQL5 Feature (Layer 4):**
- Add to `mql5/ScalpingEA.mq5` or create new include file (e.g., `mql5/OrderManager.mqh`)
- Follow MQL5 naming (PascalCase) and consult `.claude/skills/mql5-trading-ea/SKILL.md` for patterns
- EA must enforce hedging account mode (not netting)
- EA must apply risk limits locally even if Python feed stops (safety layer)

**New Dashboard View:**
- Extend `dashboard.py`; add new st.* calls (st.line_chart, st.bar_chart, st.table, etc.)
- Example: to show regime distribution per strategy, query `strategy_registry.list_strategies()`, group by regime, plot
- Remember to clear cache if modifying data loading (use `@st.cache_data(ttl=5)`)
