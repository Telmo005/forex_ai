# External Integrations

**Analysis Date:** 2026-06-30

## APIs & External Services

**Forex Broker:**
- MetaTrader 5 (MT5) - Live and historical OHLC data for forex pairs
  - SDK/Client: `MetaTrader5` Python package (Windows-only)
  - Connection: Terminal-based (must be open and logged in)
  - Authentication: Broker login credentials (passed via CLI args to `data_pipeline.py --mode mt5`)
  - Data retrieval: `mt5.copy_rates_from_pos(symbol, timeframe, 0, n_bars)` in `src/data_pipeline.py:95-102`
  - Initialization: `mt5.initialize(login, password, server)` with broker-specific server string

**Synthetic Data (Development/Testing):**
- None (data is algorithmically generated in `src/data_pipeline.py:113-150` via `fetch_synthetic()`)

## Data Storage

**Databases:**
- SQLite - Strategy registry and backtest results
  - Connection: File-based at `output/strategy_lab.db` (configurable via `STRATEGY_DB` env var in `dashboard.py:27`)
  - Client: Python's built-in `sqlite3` module (`src/strategy_registry.py:14`)
  - Schema: `SCHEMA` in `src/strategy_registry.py:18-41`
    - Table `strategies`: id, created_at, pair_a, pair_b, params (JSON), status, statistics (win_rate, profit_factor, Sharpe, drawdown, etc.), trade history

**File Storage:**
- Parquet (PyArrow backend) - Time-series features per symbol
  - Format: `output/features_<SYMBOL>.parquet`
  - Contains: log returns, volatility (fast/slow), z-score of price, range %, regime label per bar
  - Used by: `docs/hedge_engine_spec.md` for runtime spread z-score recalculation

**CSV Export:**
- Hedge candidates ranking
  - Format: `output/hedge_candidates.csv`
  - Contains: pair_a, pair_b, correlation, cointegration p-value, is_cointegrated flag, hedge_ratio_beta, spread_zscore
  - Generated by: `src/data_pipeline.py:204` (scan_hedge_candidates)
  - Consumed by: Strategy generation and future hedge_engine.py

**Caching:**
- Streamlit cache layer - 5-second TTL for strategy list loading (`dashboard.py:30-32`)
  - `@st.cache_data(ttl=5)` decorator on `load()` function

## Communication Patterns (Python ↔ MQL5)

**Current Status:**
- Not yet implemented; two approaches under consideration per `docs/risk_engine_mql5_spec.md:64-80`:

**Option 1: File-Based Queue (Simpler)**
- Python writes JSON/CSV orders to `MQL5/Files/` shared folder
- EA polls with `FileIsExist()` / `FileOpen()` every N ms
- Latency: ~100s of ms to 1s (acceptable for most cases, marginal for aggressive scalping)

**Option 2: Socket/ZeroMQ (Lower Latency)**
- Python sends orders via TCP or ZeroMQ `PUSH` socket
- MQL5 receives via `mql-zmq` DLL binding (external library required)
- Latency: Single-digit ms
- Requires additional setup but more robust at scale

## Data Flows Between Layers

**Pipeline (Layer 0) → Strategy Lab (Layer 0.5):**
- Input: `output/features_*.parquet` (features per symbol), `output/hedge_candidates.csv` (cointegration results)
- Processing: `src/strategy_generator.py` mutates parameters, `src/backtest_engine.py` runs backtests
- Output: `output/strategy_lab.db` with test results

**Strategy Lab → Dashboard (UI):**
- Input: `output/strategy_lab.db`
- Processing: `src/strategy_registry.py:list_strategies()` queries DB
- Output: Rendered in Streamlit at `dashboard.py` (equity curves, trade history, statistics)

**Validated Strategies → Hedge Engine (Layer 2, TBD):**
- Input: Strategy parameters marked as "✅ Approved" in dashboard UI
- Processing: `src/hedge_engine.py` (not yet implemented) reads parameters + live features
- Output: Proposed orders to risk_engine

**Hedge Engine → Risk Engine (Layer 3, TBD):**
- Input: Proposed orders from hedge_engine (symbol, side, hedge_ratio, trigger)
- Processing: `src/risk_engine.py` applies Kelly-fractionated sizing, exposure limits, drawdown checks
- Output: Approved orders to MQL5 EA

**Risk Engine → MQL5 EA (Layer 4, TBD):**
- Input: Approved orders (via file or socket per decision above)
- Processing: EA normalizes lot size, applies stop levels per broker limits, executes on exchange
- Output: Order confirmations, fills, and position updates back to Python for live monitoring
