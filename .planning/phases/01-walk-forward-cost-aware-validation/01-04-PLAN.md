Complete VALID-01 end-to-end: run the walk-forward revalidation mechanism (built in plan 01-03) against the market data on disk for dashboard-approved strategies, persist an honest verdict, and surface it in the dashboard — with a blocking human checkpoint that confirms whether the data is genuinely real (non-synthetic) so `revalidated_on_real_data` is never set on synthetic data (RESEARCH.md Pitfall 4).

Purpose: Satisfy VALID-01 honestly — approved strategies carry a fold-by-fold out-of-sample walk-forward verdict, and only a confirmed real-data run flips the production-eligibility flag.
Output: A `revalidate_walk_forward.py` CLI, a dashboard walk-forward panel + real-data badge, an updated known-limitations section in the spec, and a checkpoint-confirmed record of whether VALID-01 is fully satisfied (real data) or mechanism-complete-pending-real-data (fallback in effect).
