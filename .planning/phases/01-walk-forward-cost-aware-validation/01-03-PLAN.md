<objective>
Implement the walk-forward revalidation mechanism that VALID-01 requires: a new `walk_forward_validate()` entry point in `backtest_engine.py` that re-tests already-approved, already-fixed strategy parameters across sequential rolling out-of-sample folds (RESEARCH.md Pattern 2), and the additive registry columns to persist its verdict. This plan builds the mechanism and proves it on synthetic data; the actual real-data revalidation run of an approved strategy (VALID-01's real-data half) is plan 01-04.

Per RESEARCH.md Assumption A3 and the Anti-Patterns section, this is *re-validation* of frozen parameters, NOT *re-optimization* — `strategy_generator`'s mutation loop is out of scope. Per RESEARCH.md Open Question 2 (and the planning brief's locked decision), the per-fold gate is RELAXED (positive net-of-cost return + a distinct `min_trades_per_fold`), while the FULL `DEFAULT_THRESHOLDS` (profit factor, Sharpe, drawdown, min trades) is applied only to the aggregated/concatenated out-of-sample trades. Per RESEARCH.md Pitfall 3, the window is ROLLING (`max_train_size` set), never the anchored/expanding `TimeSeriesSplit` default, and the exact methodology is written down in the spec, not left implicit.

Purpose: Give the project a single, documented, cost-aware walk-forward validation code path (reusing `validate_strategy`, not a divergent second gate) that plan 01-04 runs against real market data to satisfy VALID-01.
Output: `walk_forward_validate()` + named config constants in `backtest_engine.py`, a runnable synthetic test file, additive registry columns + a `save_walk_forward_result()` helper, and the fixed methodology documented in the spec.
</objective>
