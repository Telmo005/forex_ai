<objective>
Build the MQL5 last-line-of-defense: `mql5/RiskGuard.mqh` (pure risk-check functions), `mql5/Tests/TestLite.mqh` (minimal assertion helper), and `mql5/Tests/RiskGuardTests.mq5` (standalone Script test runner). RiskGuard.mqh independently re-verifies every risk limit before an order — never trusting Python's numbers (RISK-07) — including drawdown/exposure/position-count recomputation, its own kill-switch file check (RISK-06 EA-side), mandatory stop-loss enforcement (RISK-01 EA-side), and broker lot/stop normalization. The standalone Script harness (RESEARCH.md Pattern 2) drives the pure functions with fixed adversarial inputs (RISK-08 MQL5-side) and runs in MetaEditor with no live terminal, no Strategy Tester, and no historical data — this test harness is part of THIS plan, not deferred to Phase 4.

Purpose: RISK-07's redundancy is the whole reason the risk engine is duplicated; the MQL5 side must be provably testable in isolation before the EA (Phase 4) exists.
Output: `mql5/RiskGuard.mqh`, `mql5/Tests/TestLite.mqh`, `mql5/Tests/RiskGuardTests.mq5`.

Sequencing: this plan is wave 2 and depends on Plan 01 (`02-01`). It does NOT run in parallel with Plan 01. RiskGuard.mqh hand-duplicates the exact D-locked numeric constants (Kelly fraction, drawdown %, exposure %, position count, etc.) that Plan 01 defines authoritatively in `risk_limits.py`. Running after Plan 01 completes guarantees those constants are already settled and committed, so the hand-duplication in Task 1 copies final values (not values still in flux), and the manual verification checkpoint asserts against numbers that are already the single source of truth.
</objective>
